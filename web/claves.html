Generá las dos claves de licencia

Son un par: una firma las licencias que se venden y la otra las verifica dentro del programa del cliente. Se generan acá, en tu navegador — no viajan a ningún servidor, ni al nuestro.

Hacelo una sola vez y guardalas. Cada instalador que se compila lleva grabada la clave pública. Si más adelante generás un par nuevo, las licencias que ya vendiste dejan de validar en los instaladores nuevos.

Tarda un segundo. Se usa el generador de números aleatorios del sistema operativo.

1 · Clave privada (secreta) MV_LICENSE_PRIVATE_KEY
2 · Clave pública (no es secreta) MV_LICENSE_PUBLIC_KEY

Descargar respaldo en un archivo de texto

Dónde va cada una

ValorPlataformaNombre exacto
Privada GitHub → Secrets → Actions MV_LICENSE_PRIVATE_KEY
Pública GitHub → Secrets → Actions MV_LICENSE_PUBLIC_KEY
Privada Vercel → Settings → Environment Variables MV_LICENSE_PRIVATE_KEY

La privada va en los dos lados con el mismo valor: GitHub la usa para firmar tu licencia de dueño cuando compila el instalador, y Vercel para firmar la licencia de cada cliente que paga. La pública sólo hace falta en GitHub, porque es la que queda grabada adentro del programa.

La privada no se pega en ningún otro lado. Ni en el código, ni en un correo, ni en un chat. Quien la tenga puede emitir licencias gratis del producto. Los dos lugares de la tabla la guardan cifrada y no la vuelven a mostrar.

Y después

  1. Guardá el archivo de respaldo en algún lugar tuyo que no sea el repositorio (un gestor de contraseñas, o un pendrive).
  2. Cargá los tres valores de la tabla.
  3. En GitHub, entrá a Actions → Escritorio Windows → Run workflow. Vuelve a compilar el instalador, ahora con tu clave pública adentro.
  4. Desde ese momento, cada cliente que pague recibe su licencia sola.

Esta página no guarda nada. Si la recargás, las claves que ves se pierden: por eso el respaldo.
